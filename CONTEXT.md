# NeoMind

NeoMind coordinates engineering work and preserves the relationship between requests, responsibilities, delivered artifacts, verification and project knowledge.

## Language

**Agent profile**:
A named set of duties presented to a native coding client. One profile can compose several core roles, and several profiles can share one core role.
_Avoid_: Treating a displayed profile as a separate persisted role or as proof that an agent ran.

**Core role**:
A stable responsibility used for engineering ownership, permitted operations and model policy. Profile names do not replace core role identifiers.

**Workflow**:
A saved increment relating original user intent to its execution mode, assignments, decisions and completion conditions.
_Avoid_: Treating a similar historical request as the same increment.

**Task**:
A bounded engineering assignment with an owner, authorized outputs, acceptance criteria and links to the requirements and design it addresses.

**Agent assignment**:
A bounded delegation to an actual actor under a declared profile and core role. An assignment packet describes delegation; it does not establish that launch or execution occurred.

**Reported local identity**:
An unsigned identity for attributing participation when a native client does not expose an invocation identity. It is distinct from a signed native receipt and from an activity correlation key.

**Activity report**:
A reported observation of assignment progress. Activity is distinct from execution evidence and engineering acceptance.

**Recipe**:
A versioned, parameterized procedure with an applicability contract, generator and verification expectations.

**Recipe instance**:
A recipe bound to particular parameters, engineering inputs and outputs. A new instance does not inherit historical execution results as current evidence.

**Registered procedure**:
A project script and independent check with an immutable version, parameter/output contract, declared effects and environment. Registration creates a candidate; review and actual checked runs determine eligibility for automatic reuse.

**Procedure match**:
An advisory exact, adapt, new or blocked assessment against the current request and contract. SQLite/FTS5 accelerates retrieval; authoritative manifests and current file hashes determine applicability, and execution requires separate authorization.

**Evidence**:
An observation associated with its method, inputs, output and limitations. A configured operation, requested model or proposed check is distinct from an observed execution.

**Work record**:
An actor's substantive account of its objective, inputs, decisions, results, evidence, limitations and lessons.

**Cornell note**:
A source-linked learning artifact with cues, narrative, a demonstration and separate practice and answers. It is distinct from the work record describing an actor's assignment.

**Lightweight workflow**:
An unsigned native increment using a compact, risk-based checkpoint contract. It is distinct from full engineering acceptance and cannot be substituted for a saved strict increment.

**Knowledge source**:
A provenance-bearing project or upstream artifact consulted for applicability. Retrieval similarity does not establish compatibility, authority to execute, or approval to publish.
