# WorkForce Universe — native-core

WorkForce uses VS Code **Local** chat and native subagents with WF.PM, WF.SWSD, WF.P-RES, WF.FnD, WF.Reviewer and WF.Tester. The backend retains request scope, professional reports, independent checks and product evidence. The V-model panel observes the same request; it does not run another agent engine.

Install the matching runtime and VSIX from one release. Set the **User** setting `workforce.bridge.runtimePath` to the extracted `workforce` directory containing `package.json` and `dist`. Workspace overrides are ignored. Initialize or update the intended project with `workforce init --local` or `workforce update --local`, then open it as a trusted local folder.

Run **WorkForce: Open Local WF.PM**, confirm the chat is Local, and choose your model using the native picker. Your existing custom endpoint/9router integration can supply it. No `top-models`/`worker-models` alias, model catalog file, Model Bridge connection or OpenCode bootstrap is required. Choose Allow all in the chat if desired; native consent, Workspace Trust and organizational restrictions still apply. WorkForce does not change global security settings.

Run **WorkForce: Open V-model** (the older Universe command opens this view too). Select or pin a saved request and inspect its stages, products and check evidence. Actual editor-owned native calls produce running observations; a saved assignment alone is not proof an agent is running. **Role models…** uses the current native inventory and sets a preference for the role's next delegation. Omitted preferences inherit the parent; WF.PM's own model remains controlled by its chat picker. Requested and observed provider identity remain separate.

Give WF.PM a normal requirement in your own words, with the relevant folder attached. The manager discovers reusable project tools and capabilities, prepares one professional plan and delegates workers. Native chat shows their actual names and tool calls. A direct role job completes only that role's scope; whole-product acceptance requires independent review/testing and current checks. Continue an unfinished request with its returned public request key instead of creating a replacement. Closing the view does not cancel work; closing VS Code cancels owned execution and retains results for reconciliation.

**Plug-ins** retains optional REA, CodeGraph, Context7 and Playwright installation/connection controls. Explicit approval, exact pins, project network policy and observed tool discovery remain distinct from successful use. Native MCP bindings grant only User-approved exact observed tool references to selected roles. Disable/remove denies new admissions and defers owned cleanup until active users finish. Existing optional REA support is retained; no new REA service starts during extension activation.

**Manage Native Capabilities** and **Manage Native Package Registrations** use standard VS Code controls for approved portable skills and complete pinned native packages. Source approval comes from User settings; workspace settings cannot add trust. Packages do not replace WorkForce roles or grant MCP tools. Missing optional capabilities fall back to suitable ordinary project tools, and explicit User disable/remove is preserved. Installation or registration is not evidence of loading, use or product acceptance.

**Reusable tools** opens the Automation Library. SQLite/FTS5 retrieval finds earlier work; task family, inputs, script versions, environment, scope, permissions and checks still determine eligibility. Similarity alone cannot authorize execution.

**Focus Space** retains the countdown, calendar import/read-only feeds, weather, YouTube and original ambient music. Ambient audio continues when returning to the V-model or another tab and stops when paused or the panel closes. YouTube retains visible-player restrictions and may require external playback for restricted videos/origins. Private calendar and YouTube credentials stay in this extension's SecretStorage.

This release defers **M7's new native REA provider and embedded managed 9router gateway**, including their model-provider commands/settings and archive. The source/research remain in the repository for later work. Native model providers configured by the user continue to work directly. Compatibility MCP exposes saved status and advisory reuse discovery; it does not substitute for editor-owned dispatch.

Build the VSIX with `npm run extension:package` from the repository root. It packages only the explicit native-core manifest file list and does not publish to the Marketplace. Follow the matching runtime's `docs/install-release.md` for release installation and its validation report for actually tested platforms and client journeys.
