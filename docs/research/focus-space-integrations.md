# Focus Space integration findings

Research date: 2026-10-23. This document separates inspected code and official platform behavior from proposed implementation. No personal calendar events, access tokens or credential values were read; no calendar was published or modified.

## Recommended first release

Build a personal agenda with local `.ics` import, optional subscription to an **already available** Google/Outlook ICS feed, and local focus blocks linked to imported events. Show event times, free gaps, source and last refresh; a focus block is a local plan rather than an external calendar appointment. Offer an explicit browser link to the provider for edits. Do not ask the user to publish a private calendar to enable the feature.

Keep parsing and slot calculation independent of network, VS Code and credentials. A host provider retrieves approved feeds; a bounded parser expands calendar occurrences; the webview receives only display data. The parser must report incomplete expansion so the UI does not imply that an incomplete agenda establishes free time.

| Path | Useful now | Actual connection requirement |
| --- | --- | --- |
| Local ICS file | Offline agenda and focus planning | User selects a file; a snapshot does not refresh itself |
| Existing ICS subscription | Read-only provider updates | User supplies an existing feed URL; store a private URL as a secret |
| Google OAuth | Authenticated read-only agenda | Dedicated desktop OAuth setup and tested consent/token flow |
| Codex Calendar connector | Available to this chat | Does not authenticate the installed VS Code extension |

Google documents the secret iCal address as a read-only subscription method. Possession of that URL grants access, so it must not enter webview state, workspace configuration, logs or engineering archives. Outlook's documented Internet Calendar path involves publication; its URLs can be viewed by anyone possessing the link. Accept an existing permitted subscription or a local export, and leave publishing as a separate user decision. [Google iCal subscriptions](https://support.google.com/calendar/answer/37648?hl=en), [Microsoft Internet Calendar publication](https://support.microsoft.com/en-us/outlook/introduction-to-publishing-internet-calendars).

## What NeoWeb already supplies

The inspected fetched `main` revision is `48570aeb5ef96c83945c404790dfebc5d4b7b811`. The local working branch is different; its unrelated changes were left intact. NeoWeb's `CalendarClient` uses Google Identity Services' browser token client, requests `calendar.events.readonly`, and calls `GET /calendar/v3/calendars/primary/events` with `singleEvents=true`, `orderBy=startTime`, `maxResults=10` and a current `timeMin`. Tokens stay in memory; expiration requires reconnection. This is a real read-only client implementation, **not evidence of a currently authorized account** or a reusable local calendar server. [Pinned client source](https://github.com/NeoTech-vietnam/NeoWeb/blob/48570aeb5ef96c83945c404790dfebc5d4b7b811/web/lib/integrations.ts).

The UI obtains client IDs from browser-local connection settings. Only the presence of `NEXT_PUBLIC_GOOGLE_CLIENT_ID` and `NEXT_PUBLIC_SPOTIFY_CLIENT_ID` configuration keys was checked; nonempty values alone do not prove authorization, an accepted JavaScript origin or a usable token. The current client reads only the primary calendar and returns starts but not the event end/duration needed for reliable focus-gap calculation. No local calendar API route was found in the inspected static application. Reuse its connection-state/error design and event display ideas, rather than transplanting its web OAuth popup. [Pinned UI source](https://github.com/NeoTech-vietnam/NeoWeb/blob/48570aeb5ef96c83945c404790dfebc5d4b7b811/web/components/portal/personal.tsx), [deployment architecture](https://github.com/NeoTech-vietnam/NeoWeb/blob/48570aeb5ef96c83945c404790dfebc5d4b7b811/docs/deployment.md).

## Calendar semantics and limits

ICS is structured calendaring data. Correct expansion includes `RRULE`, `RDATE`, `EXDATE`, `RECURRENCE-ID` overrides, `VTIMEZONE`, all-day dates and exclusive `DTEND`; a line-based homegrown event splitter would silently misplan recurring work. Use a pinned, licensed calendar library such as ICAL.js. Its event layer relates overrides and expands recurrence sets, but its stock package does not supply an IANA timezone database: honor embedded timezone definitions and report unresolved/floating zones instead of silently treating them as verified local time. [RFC 5545, event semantics](https://datatracker.ietf.org/doc/html/rfc5545#section-3.6.1), [ICAL.js event API](https://kewisch.github.io/ical.js/api/ICAL.Event.html), [timezone distribution limitation](https://kewisch.github.io/ical.js/api/).

The isolated implementation in `src/focus-calendar.ts` uses a 1 MiB input, a 31-day query horizon, 500 projected events and 10,000 recurrence iterations. It imports no attachments, executes no alarms and makes no network requests from calendar content. Cancelled instances do not block a slot; transparent events remain visible but do not block. It merges overlapping/adjacent busy intervals before finding gaps and returns warnings plus an incomplete flag when limits or unsupported data prevent a complete result. The host should withhold confident free-slot recommendations for incomplete data.

This adapter supports common daily/weekly/monthly/yearly patterns and unfiltered subdaily rules through ICAL.js; it deliberately rejects unsafe filter combinations, range overrides and RDATE periods with an incomplete warning. It preserves stable occurrence identities across moved overrides and matches UTC exception identifiers to time-zoned series. It does not claim full RFC 5545 conformance. All-day ISO midnight values represent calendar dates, so the host must preserve those dates when displaying them. `findFocusSlots` accepts an optional validated IANA `timeZone` (default `UTC`) and resolves each all-day date boundary in that zone, including 23/25-hour DST days. Parsing conservatively retains neighboring all-day dates for accurate partial-local-day planning; timed events retain exact query filtering.

For a future Google API provider, keep the read-only scope and request both lower/upper time bounds. `singleEvents=true` can let Google expand recurrences, but pagination still matters; a full page is not proof the agenda is complete. Adding a calendar picker requires its own calendar-list read permission. Keep manual refresh and cache age explicit before considering incremental sync. [Calendar scopes](https://developers.google.com/workspace/calendar/api/auth), [events.list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list).

## Real Google authorization path

Google prohibits developer-controlled embedded user agents for authorization. A VS Code webview is therefore not a suitable place to embed Google's consent page. For Windows desktop, use a separately configured Desktop OAuth client, system browser, PKCE, state validation and a short-lived loopback callback listener. Keep tokens in extension-host `SecretStorage`, whose implementation is encrypted and platform specific; do not send them to the webview. [Google OAuth policies](https://developers.google.com/identity/protocols/oauth2/policies), [desktop flow](https://developers.google.com/identity/protocols/oauth2/native-app), [VS Code secret storage](https://code.visualstudio.com/api/references/vscode-api#SecretStorage).

The current extension declares a workspace extension host. SSH, containers and browser VS Code complicate a loopback callback because the host may be remote from the user's browser. Support local desktop first or implement and test the external-URI/forwarding path separately. A settings form or a saved client ID must be labeled configured/disconnected until actual authorization and a successful calendar read occur. [Remote extension networking](https://code.visualstudio.com/api/advanced-topics/remote-extensions).

## Webview, weather and music constraints

The existing monitor uses `default-src 'none'` with local styles and nonced scripts, so external API fetches and YouTube frames are currently blocked. Give Focus Space its own resource/controller boundary. Keep feed/weather fetches in the extension host with explicit provider allowlists, bounded bodies, timeouts and safe errors; do not add a generic URL-fetch proxy. Validate postMessage inputs and display text through DOM text nodes. The webview should receive source labels and timestamps, never raw private feed URLs or OAuth tokens. [VS Code webview security](https://code.visualstudio.com/api/extension-guides/webview#security).

**Desktop webview geolocation must have a fallback.** VS Code 1.143.1's official Electron permission handler only permits a small webview permission set that excludes geolocation; requests are refused. This is stronger evidence than assuming a normal browser permission prompt will appear. Offer explicit city search/coordinates and label the result as that selected location. Never silently substitute an IP-derived/default city under “current location.” In a browser host that actually permits geolocation, request it only on user action, handle denial/unavailable/timeout, and avoid continuous tracking. [Pinned VS Code permission handler](https://github.com/microsoft/vscode/blob/1.143.1/src/vs/code/electron-main/app.ts#L253-L280), [Geolocation error/consent behavior](https://www.w3.org/TR/geolocation/#position-error).

Open-Meteo is a plausible optional weather provider with latitude/longitude requests and explicit forecast timestamps/units. A displayed forecast is provider data for the selected coordinates, not proof of GPS access or a live local sensor measurement. No weather request or location lookup was made in this audit. [Forecast API](https://open-meteo.com/en/docs).

For YouTube, load an official embed only after a user action and allowlist its frame origin rather than arbitrary iframe URLs. Validate video/playlist IDs, keep playback controls and an “Open in browser” action, and do not assume autoplay works. Error 153 explicitly covers missing HTTP Referer/equivalent client identity, and owners can prohibit embedding; a VS Code webview needs an actual playback test before claiming success. `youtube-nocookie.com` is Google's documented privacy-enhanced web embed option, not a promise of zero third-party requests or guaranteed desktop-app behavior. Do not spoof identity headers or proxy/download the media. [Player errors and requirements](https://developers.google.com/youtube/iframe_api_reference), [embed/privacy options](https://support.google.com/youtube/answer/171780?hl=en).

## Verification before calling a provider connected

Use synthetic ICS fixtures for recurrence overrides, exclusions, DST, all-day boundaries, cancellation, transparency and limit exhaustion. Test overlapping/back-to-back meetings against exact free slots. Test feed failures without exposing URLs and show cached/stale data explicitly. Exercise real OAuth or feed retrieval only with an explicitly supplied connection; do not query personal events merely to demonstrate tool availability. Validate the installed webview's iframe playback and denied-location fallback independently of browser-preview screenshots. Personal agenda/focus state belongs in extension storage, separate from NeoMind engineering evidence and acceptance gates.
