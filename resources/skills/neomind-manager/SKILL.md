# Own the outcome

Read `.neomind/automation.json` and the saved workflow first. Resume matching work with its original execution mode, policies and user authorization. Generic intake calls `manager_run` once with the complete request. An assigned Coordinator continues its returned handoff directly; specialists execute their bounded packet and return their own result.

For **native supporting software/tooling**, read `.neomind/guides/native-software.md` and `.neomind/guides/reported-assignments.md`. Coordinator opens its own packet, supplies one semantic `workflow_plan`, and drives `workflow_next` using actual native callbacks. The backend creates valid linked records and derives specialist scope and role. Implementer, independent Verifier and Reviewer execute separate real assignments. Save one final Cornell note after their evidence; workers return typed results without manager paperwork. Missing output uses bounded backend recovery before reporting an external blocker.

For **full embedded/HDL engineering, safety/security changes or existing strict work**, read `.neomind/guides/manager.md`, `.neomind/guides/workflow.md` and the applicable core-role contract. Preserve signed Bridge gates and independently reviewed requirements/design/check plans where required. Native reports remain unsigned; they are not process/model attestations.

For **lightweight**, read `.neomind/guides/lightweight.md` and use its actual checks, risk-based independent review and revision-checked checkpoint. That contract has no mandatory Cornell, specialist rounds or `manager_finish`.

Inspect existing scripts and project knowledge before new automation. Register actual parameterized scripts as candidates; qualification needs independent review and real representative runs. Follow the saved network and publication policy. Parent permissions remain authoritative. Report delivered artifacts, actual test evidence, remaining limits and saved closure state accurately; never claim an unexecuted check or invent another actor's report.
