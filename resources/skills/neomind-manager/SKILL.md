# Own the engineering outcome

Read `.neomind/automation.json` first. For new ordinary requests selecting `execution_mode: lightweight`, follow `.neomind/guides/lightweight.md` instead of the strict procedure below. Start `manager_run` once, execute its native `neomind-lightweight` handoff with the configured strong model, and checkpoint actual progress. Already assigned lightweight agents continue directly. Keep strict increments unchanged; unsigned reports are not signed acceptance. Lightweight work has no mandatory specialist rounds, Cornell exercises, archives or PRs. Escalate safety/security or explicitly strict work before mutation.

Read `.neomind/guides/manager.md` and `.neomind/roles/manager.md`. Follow the manager procedure automatically when the user gives engineering intent; the user does not need to name a role, invoke a skill, or operate the CLI.

Start by inspecting persisted workflow state and installed policies. When `.neomind/routing.json` exists, the intake agent automatically invokes `manager_run` with the user's requirement or requirements array. Observe and resume the managed native coordinator through status, bounded waits, and native resumption. An already bound manager or specialist follows its packet without recursively launching another coordinator. Legacy projects without routing policy retain the `manager_begin` procedure.

Complete the increment through actual core operations and signed native invocations. Read `.neomind/routing.json` for the authoritative strong model, ordered worker models, provider choices, and requested reasoning effort. Regenerate managed client agents with `neomind update` after policy changes. Copilot model selection uses the generated `.github/agents` files; the Codex app-server bridge cannot execute this policy. Strict Copilot dispatch uses the installed VS Code model bridge; require actual current signed receipts and report real bridge limitations. Lightweight client-side work remains unsigned. Resolve role capabilities and reviewed recipes before dispatch. Record discussion, protected expectations, final decisions, substantive work records, Cornell demonstrations/practice, verification evidence, separate review, and acceptance. Use saved policy for automatic private archives and generalized draft contribution PR creation. MCP is preferred; consult `neomind --help` for agent-operated CLI fallback.

Report decisions, delivered behavior, evidence, documentation, task status, contribution PRs, and any real blocker. Ask only for missing product intent or a required external action. A blocked native capability remains a recorded limitation; it is never replaced by an invented success.
