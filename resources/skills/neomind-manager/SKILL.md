# Own the outcome

## Backend-owned session

An explicit NeoMind-owned role/stage packet and bound tools select this branch. Coordinator inspects the supplied request and readable project context, uses advertised `work_prepare` to assess reusable procedures, and saves one bounded semantic `workflow_plan` followed by one compact `assignment_report`. Specialists resolve their assigned question and save their own compact result. The backend opens workers, binds identities and advances verification, review and closure. Use the runtime-provided controlled-workflow guide for payload and report-stage details.

Follow the canonical plan example in the current tool description or runtime guide: `checks` contains independent commands and their `negative_controls`; a direct script step uses `command` and `output_paths` within `execution_steps`. The producer's bound script runner later receives the step title and prepared data through `input_path`, which becomes JSON stdin. Keep the professional approach in `rationale`. Declare Cornell compilation through `cornell_output_dir` and optional `cornell_input_path`; the compiler owns its canonical note/practice/answer files.

## Client intake and other saved modes

For controlled client intake without a worker packet, call `manager_run` once with the complete requirement, or resume the exact saved receipt through `manager_control`; use `manager_status` when status is requested. The branches below apply only to a matching saved non-controlled execution mode and preserve its existing contract.

The requirement retains the full product goal and all acceptance, process, scope, preservation and safety obligations. Use `execution_mode` for runtime dispatch and the status/control tools for client operations; those operations do not request product orchestration changes. Preserve actual authentication, storage, execution and orchestration requirements. Retain ambiguous mixed requests completely; the backend remains conservative. See the controlled-workflow guide's client entrypoint for this boundary.

For a new intake, copy the complete user requirement verbatim. Do not append runtime operating instructions, inferred review gates, extra acceptance criteria or invented report files. The backend supplies dispatch, verification and final workflow reporting. Resolve explicit references to earlier user requests from their saved context without inventing obligations.

Read `.neomind/automation.json` and the saved workflow first. Resume matching work with its original execution mode, policies and user authorization. Generic intake calls `manager_run` once with the complete request. An assigned Coordinator continues its returned handoff directly; specialists execute their bounded packet and return their own result.

For **native supporting software/tooling**, read `.neomind/guides/native-software.md` and `.neomind/guides/reported-assignments.md`. Coordinator opens its own packet, supplies one semantic `workflow_plan`, and uses the client workflow driver described there. The backend creates valid linked records and derives specialist scope and role. Implementer, independent Verifier and Reviewer execute separate real assignments. Save one final Cornell note after their evidence; workers return typed results without manager paperwork. Missing output uses bounded backend recovery before reporting an external blocker.

For **full embedded/HDL engineering, safety/security changes or existing strict work**, read `.neomind/guides/manager.md`, `.neomind/guides/workflow.md` and the applicable core-role contract. Preserve signed Bridge gates and independently reviewed requirements/design/check plans where required. Native reports remain unsigned; they are not process/model attestations.

For **lightweight**, read `.neomind/guides/lightweight.md` and use its actual checks, risk-based independent review and revision-checked checkpoint. That contract has no mandatory Cornell, specialist rounds or `manager_finish`.

Inspect existing scripts and project knowledge before new automation. Register actual parameterized scripts as candidates; qualification needs independent review and real representative runs. Follow the saved network and publication policy. Parent permissions remain authoritative. Report delivered artifacts, actual test evidence, remaining limits and saved closure state accurately; never claim an unexecuted check or invent another actor's report.
