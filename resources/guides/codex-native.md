# NeoMind in Codex

Use this guide for Codex intake, delegated expert work and saved `codex-native` increments. Read the project's saved automation and network policies first. Resume matching work; keep its saved mode and client. Existing strict work stays on its signed Bridge path.

## Intake and delegation

When the native client omits invocation identity, follow `reported-assignments.md`: Coordinator prepares each actual delegate packet; that delegate claims its server-issued local identity and persists its own reports with `reported_assignment`. Missing platform IDs do not prevent validated local research/report persistence. Local IDs remain unsigned and never replace signed strict receipts or prove independent execution.

1. Generic intake calls `manager_run` once with the full request. Use the returned `handoff.agent` as Codex `spawn_agent.agent_type`, passing `handoff.prompt` unchanged. An assigned `neomind-coordinator` continues directly; it does not create another workflow or launch itself.
2. Coordinator assigns bounded work to `neomind-explorer`, `neomind-researcher`, `neomind-planner`, `neomind-architect`, `neomind-implementer`, `neomind-debugger`, `neomind-verifier` and `neomind-reviewer` as applicable. Each packet names workflow, assignment, profile, core role, allowed paths, inputs, acceptance criteria and evidence. Keep at most three independent workers; serialize shared edits and terminal operations.
3. Reuse first: inspect existing source, local knowledge and applicable skills. Use reviewed pinned upstream adapters with their licenses and provenance. Under `local-only`, discovery and research stay local; record upstream work as not searched. A failed request is not a no-match.
4. Wait for actual delegate results. Specialists keep their declared duties, return actual invocation IDs when available and escalate blockers. Profile names never replace the twelve persisted core role IDs. Implementer and Debugger share `developer` model policy; Verifier uses the strong `verifier` policy.

## Saved lifecycle

For full `codex-native` increments, keep requirements, independent design/check review, scoped implementation, immutable verification evidence, independent acceptance, seven-section assignment reports, substantive Cornell delivery and manager closure. Research-only assignments save real source findings and applicable inspection evidence. Preserve unmet gates as blockers. Native IDs and observations are unsigned reports, never runtime attestations or confirmed model claims.

For a `lightweight-workflow`, follow `lightweight.md`: a short plan, actual checks, risk-based independent review and revision-checked `lightweight_checkpoint`. Assignment reports, `manager_finish` and Cornell closure do not apply to that lightweight contract. A saved lightweight backend is immutable; use a new increment to change clients.

Report actual progress through `agent_activity` with the supplied workflow/assignment/profile binding. A dispatch is a launch attempt; running starts only when observed. Missing activity expires to unknown. Progress and native lifecycle hooks do not prove completion, acceptance or a model identity.

## Native limits and models

Codex custom agents inherit the parent session's permissions, provider and MCP connections. Profile read-only duties are behavioral boundaries; their files do not create independent sandboxes or a signed capability gateway. Use available native tools within the assigned duties and parent permissions. Missing required browser, embedded, HDL or hardware facilities block those claimed results.

Codex models inherit the parent by default. Explicit platform-specific `config.json` model tiers may select an exact Codex model. An opt-in `codex_routing: "9router"` uses the configured router and core-role policy for new agents; provider configuration alone does not establish Responses/SSE or tool-call compatibility. Keep credentials in the referenced environment variable. Review generated configuration conflicts and trust changed project hooks through Codex's normal review flow.
