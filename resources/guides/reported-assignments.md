# Missing native invocation identity

Use this fallback only for full `copilot-native` or `codex-native` workflows when the client does not expose a usable invocation ID. Keep strict Bridge receipts and lightweight checkpoints unchanged. Missing identity is an internal persistence concern: continue authorized work through these tools instead of asking the human to repair ordinary records.

1. Coordinator calls `assignment_prepare` with saved `workflow_id`, exact `profile_id` and core `role`, a unique stable `assignment_id`, substantive `objective`, and `task_id` when assigned. For Coordinator's own work use profile `coordinator`, role `manager`. An identical retry returns the same local identity; a new assignment needs a new assignment ID.
2. Launch the actual specialist and pass the returned packet's `id` and `claim_token` privately. Coordinator never claims a specialist packet, writes its report or substitutes self-review for independent review.
3. The actual delegate calls `assignment_open({packet: {id: packet.id, claim_token: packet.claim_token}})` and privately retains its returned `handle`. Before opening, omit `reported_assignment` entirely; blank IDs/tokens and empty objects are invalid credentials. The packet's stable assignment correlation label is not the server-issued packet ID. Include `reported_assignment: handle` on subsequent NeoMind MCP calls. `assignment_context` derives workflow/task/role and returns the exact result schema. `assignment_progress` needs only state and summary. Low-level `assignment_claim` remains a compatible recovery operation.
4. Researcher/Explorer inspect real sources and call `knowledge_search` and `knowledge_research`; the latter validates paths, source evidence and rationales and computes hashes. No terminal access is required for these metadata operations. Each specialist calls `manager_discuss` only if its core-role operations permit it, then saves `assignment_result` using the context's substantive schema. The runtime validates source/artifact references and renders the seven-section report. Return saved record IDs and real findings without credentials. Low-level `assignment_report` remains available; protected record fields are never part of a typed result patch.
5. The actual producer edits through its available native editor/terminal inside the assigned task scope and records real checks. `task_file_write` remains the strict signed Developer gateway. An independent Reviewer claims its own packet and reviews the final baseline. Coordinator completes research, planning, evidence, review, Cornell and closure gates.

Match the core role to the operation. Planner uses `requirements`, Implementer/Debugger use `developer`, and the combined Verifier profile needs separate bounded assignments for `verifier` (check-plan authorship) and `check-executor` (prescribed execution and evidence). The actual Verifier can claim both assignments for those duties; final independent review still belongs to a separate Reviewer.

Tasks link `satisfies` to their requirement and `implements` to their design; checks link `verifies` to the engineering inputs they cover. Re-read current records after correcting a plan or after Coordinator prepares task metadata. Refresh affected specialist contributions and independent reviews against the changed baseline, then retry the decision. Correcting ordinary trace links or stale review inputs is Coordinator work and does not require human intervention. Never remove a real gate or report an unsuccessful operation as completed.

These `local-report-*` identities are server-issued correlation and unsigned participation claims. Records retain `assurance: unsigned-native-report` and identify their source through `identity_assurance: unsigned-local-assignment` and `reported_assignment_id`. They are not platform IDs, signed receipts, model observations or proof of independent processes. A shared trusted client can possess a claim token; real delegation and independence must still occur. Never use a local ID with `native_status` or invent a native ID. An actual permission or required-tool refusal remains a blocker for the result it prevents.
